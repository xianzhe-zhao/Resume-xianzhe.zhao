三、D3 面试题库设计

种子：handoff/面试准备清单.html 的 45 题 7 分类（A 开场5/B RAG 9/C 11/D 7/E 5/F 5/G 3）。

3.1 数据层 data/interview.json

{
  "categories": [
    {
      "id": "rag", "label": "RAG 系统",
      "items": [
        {
          "id": "rag-pgvector",
          "q": "为什么用 pgvector 不用 Milvus？",
          "a": ["已有 PostgreSQL...", "引入新组件成本..."],
          "tags": ["必答"],
          "rel": ["experience.0.projects.0"],
          "dirs": ["ai", "fullstack"]
        }
      ]
    }
  ]
}
字段用途
id题目唯一标识
q问题
a答案要点数组
tags必答/高频/诚实作答
rel关联 resume.json 字段路径（简历改动时提示复核）
dirs所属求职方向（ai/fullstack/erp/pm），实现按方向筛选

3.2 API 层（server.js 新增）

API方法鉴权用途
/api/interviewGET公开返回 interview.json（脱敏无需，全是题目）
/api/interview/savePOST需登录保存题库（复用 /api/save 鉴权机制）

3.3 Admin 层（admin.js 新增 tab）

  • 顶部新增「面试题库」tab（与版本 tab 并列）
  • 按分类列表 + 行内编辑（q/a/tags/dirs）+ 增删题目/分类
  • 按 dirs 方向筛选（复用 handoff 清单的 chip 筛选交互）
  • 编辑后即时预览

3.4 同步机制（关键）

简历改动后只提示复核，不自动改写答案（避免事实漂移）：每条答案通过 rel 绑定简历字段；简历保存时扫描被改字段；后台提示「以下 N 条面试答案引用了你刚修改的经历，请复核」。
